# 操作记录

> **维护对象**：任何 AI 助手和人类读者。
> **目的**：记录每一次对代码或文档有实际变更的事项，防止上下文在长会话或跨会话中丢失。

## 维护规范

1. **每个条目必须有状态**：🟢 已完成 / 🟡 进行中 / 🔴 废弃
2. **废弃条目处理**：确认无历史参考价值后删除；有保留价值的（如设计方向曾被尝试后放弃）改为废弃态并注明原因
3. **新条目追加**：按时间顺序，新增在同 Phase 节末尾或创建新节
4. **内容底线**：做什么 + 为什么 + 结果。不记录纯讨论/调研，只记录对代码或文档产生了实际变更的事项
5. **时效性**：进行中的条目超过 7 天无更新，主动询问是否仍有效或标记废弃

### 登录接管原理勘探与轮询修复

- **做什么**：用户实测 onUpdateVisitedHistory 接管不生效（登录后仍出现网页"选择你所在的团队"），要求实际搞明白登录原理。抓取 Hikiot 登录页 HTML 与前端 JS bundle 逆向确认。
- **原理结论**（前端 JS 代码实证）：登录页为 Vue SPA（vue-router）；登录接口为 `POST /api-saas/open/v1/codeLogin`（验证码）/`pwdLogin`（密码），发送验证码为 `POST /api-saas/open/v3/sendMessage`（需阿里云滑块 nvcVal）；登录成功后网页 JS 将 `data.token` 写入 localStorage 并手动 setCookie `www_token`（domain=.hikiot.com, Secure，cookie 名按环境映射，生产为 www_token）；随后 SPA 路由跳转团队选择页（chooseYourTeam，团队数据来自 `GET /api-saas/v1/team/listAll`），选团队调 `team/change`。
- **根因**：Android WebView 的 `doUpdateVisitedHistory` 只在真实导航/历史条目变化时触发，SPA 的 history.pushState 不产生 WebView 历史条目，onUpdateVisitedHistory 探测不触发（inappwebview_android 源码确认映射关系）。
- **结果**：改为**每秒轮询 document.cookie**——登录期间 Timer.periodic 注入 JS 读 cookie，www_token 一出现立即由 App 接管（保存 token → 主框架 → 原生团队选择一次），不依赖任何 WebView 回调；onLoadStop/onUpdateVisitedHistory 保留为兜底。
- **验证**：`flutter analyze` 无问题；`flutter test` 148/148 通过；`flutter build apk --debug` 成功。
- **遗留**：验证码登录需滑块（nvcVal）与短信验证码，自动化模拟被风控阻断，未端到端实测；轮询接管后的实际体验（网页选择页闪现时长）需真机验证。CLAUDE.md/AGENTS.md 已同步修正 SPA 事实。
